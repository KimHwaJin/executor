# Artifact 파일명 및 경로 규칙

## 적용 범위

분석 코드가 Jupyter 저장소에 생성한 아티팩트의 폴더와 파일명에 적용한다.
공백, 한글, 유니코드, 괄호, 점, 밑줄, 하이픈을 허용한다.
파일명을 임의로 치환하거나 Unicode 정규화하지 않는다.
별도의 255글자 제한 대신 실제 파일시스템의 이름·경로 길이 제한을 따른다.
사용자·프로젝트·세션 ID로 만드는 Executor 작업 경로의 기존 검증은 유지한다.

## 금지 규칙

- 경로 요소가 정확히 `..`인 상위 경로 이동. `file..png`는 허용한다.
- NUL, 개행, 탭, DEL 등 Unicode Cc 제어문자.
- 역슬래시. API 경로의 폴더 구분자는 `/`이고 파일명에는 사용할 수 없다.
- 심볼릭 링크를 해석한 실제 경로가 Jupyter 루트 밖인 경우.
- 실제 파일시스템에서 지원하지 않는 이름 또는 길이.

메타데이터 조회와 다운로드는 파일만 허용하며 디렉토리는 거절한다.
기존 루트 내부 절대경로 지원은 유지하지만 절대경로에도 동일한 금지 규칙을
적용한다. 상대경로 기준은 Jupyter 루트이며 Executor/Agent 공유 PV가 아니다.

## 일관성 및 오류

탐색, 메타데이터 조회, 다운로드가 같은 Jupyter 경로 검증을 사용한다.
탐색 시 금지 파일이나 외부 링크를 발견하면 조용히 누락하지 않고 오류로 반환한다.
Executor의 Artifact manifest 경로도 상위 이동, 제어문자, 역슬래시를 거절한다.

메타데이터 API의 422는 연결 단절이 아니라 요청 검증 실패일 수 있다.
Executor는 알려진 고정 경로 오류 메시지만 diagnostics에 덧붙인다.
임의의 응답 본문, 절대경로, 토큰은 오류 메시지에 복사하지 않는다.
기존 failure 분류, REST/MCP 응답 및 Redis 이벤트 필드에는 변경이 없다.

## 배포 및 검증

독립 배포용과 테스트용 Jupyter 확장에 같은 변경이 적용된다.
Jupyter 확장을 업데이트하고 서버를 재시작해야 파일명 허용이 반영된다.
Executor도 업데이트하면 manifest 검증 및 상세 오류 전달이 반영된다.
DB 마이그레이션은 필요 없다. 이미 실패한 등록을 자동 복구하지는 않는다.

검증에는 공백·한글·괄호·숨김 파일·연속 점 이름, 제어문자, 상위 이동,
외부 심볼릭 링크, 디렉토리 거절을 포함한다.
실제 Jupyter 커널에서 문제의 histogram 파일명을 사용한 PNG를 생성하고
Artifact 탐색 및 메타데이터, 원본/Range 다운로드를 검증한다.
